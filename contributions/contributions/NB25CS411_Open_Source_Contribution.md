## 1. Introduction

Open-source software engineering is the process of developing and improving software whose source code is publicly available. Developers can collaborate, identify problems, fix errors, and improve documentation.

GitHub is a platform used to manage open-source projects and contributions.

## 2. Problem Analysis

A group of developers is working on an open-source Library Management System hosted on GitHub.

The project does not contain proper documentation explaining how users can issue and return books.

This creates problems such as:

- New users may not understand how to use the system.
- Students may face difficulty issuing books.
- Users may not know the correct book-return procedure.
- Developers may receive repeated questions about the system.

Therefore, proper documentation is required.

## 3. Proposed Solution

The student can contribute to the project by creating or improving a documentation file explaining the book-issuing and returning process.

### Importance of Open-Source Contributions

1. Improves software quality.
2. Helps developers share knowledge.
3. Makes software easier to understand.
4. Encourages teamwork and collaboration.

### Steps to Fork the Repository

1. Log in to GitHub.
2. Open the original Library Management System repository.
3. Click the Fork button.
4. Select the student's GitHub account.
5. Click Create fork.

A copy of the repository is created in the student's account.

### Creating or Modifying Documentation

1. Open the forked repository.
2. Navigate to the documentation folder.
3. Create or edit a Markdown file.
4. Add instructions for issuing and returning books.
5. Save the changes.

### Book-Issuing Procedure

1. Log in to the Library Management System.
2. Search for the required book.
3. Check book availability.
4. Select the Issue Book option.
5. Confirm the issue request.

### Book-Returning Procedure

1. Log in to the system.
2. Open the issued-books section.
3. Select the book to return.
4. Click Return Book.
5. Confirm the return.

### Committing Changes

1. Click Commit changes.
2. Enter a meaningful commit message.
3. Commit the documentation file to the student's fork.

### Submitting a Pull Request

1. Open the student's forked repository.
2. Click Contribute.
3. Select Open pull request.
4. Verify the original repository and branches.
5. Enter a suitable Pull Request title.
6. Click Create pull request.

The project maintainer reviews the changes and can merge them into the original repository.

## 4. Benefits and Challenges

### Benefits

- Improves project documentation.
- Makes the system easier for users.
- Encourages collaborative development.
- Helps students gain GitHub experience.
- Reduces confusion about library operations.

### Challenges

- Contributors must follow project guidelines.
- Changes may require review and corrections.
- Merge conflicts may occur when multiple developers edit the same file.

## 6. Conclusion

Open-source contribution helps improve software through teamwork and collaboration. By adding proper documentation to the Library Management System, students can make the application easier to use.

GitHub provides a simple process for forking repositories, committing changes, and submitting Pull Requests. This improves software quality and encourages collaborative software development.
